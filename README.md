## 一、先认清：Claude 有三笔互不通用的账

Anthropic 的付费系统是分开的，这一点几乎所有教程都一带而过，但它恰恰是大部分人踩坑的第一现场。

| 你实际在买什么 | 在哪里付 | 计费方式 | 能不能当 API 用 |
| --- | --- | --- | --- |
| Claude Pro / Max 订阅 | claude.ai 的设置页 | 按月订阅 | 不能 |
| Claude API 额度（credits） | console.anthropic.com → Settings → Billing | 预充值，按 token 扣 | 能 |
| Claude Code | 两条线：CLI 默认走 API 额度；订阅版走 Pro/Max | 视情况 | 看走哪条 |

一句话概括：

- **充了 Pro，不等于有 API 额度。** Pro 是网页端和 App 的会员权益，跟开发者 key 是两码事。
- **充了 API 额度，也不能解锁网页端会员。** API credits 绑定的是你 Console 里的组织，跟你登录 claude.ai 的那个账号权益无关。
- **Claude Code 的 CLI 默认吃 API 额度。** 你如果只是想用 Claude 写代码、又不想碰 API 计费，走 Pro 订阅那条线更省事；但如果你要把它接进 CI、脚本或者自己的服务里，那 API 这笔账躲不掉。

先把这三笔分清楚，后面的选择才有意义。

## 二、官方充值的流程本身很简单，难的是门槛

如果你人在 Anthropic 支持的地区、手里有能用的海外卡，Claude API 充值这件事其实五分钟就完事了：

1. 登录 console.anthropic.com，进 **Settings → Billing**；
2. 点 **Add payment method**，填卡号，账单地址必须和卡上的完全一致；
3. **Buy credits**，首次充值金额门槛不高，个位数美元就能开始；
4. 打开 **Auto-reload**，设一个阈值（比如低于 10 美元自动补充）——这是整个计费页里最值得点的一个开关，生产环境因为余额耗尽而中断的情况几乎都由此避免；
5. 给每个项目、每个环境单独建 API key，别用一个共享 key，否则账单出来你根本不知道钱花在哪。

几个容易被忽略的细节：

- **额度会过期。** 预充值的 credits 有有效期，别一次囤一年的量。
- **限额随累计消费提升。** 用量等级（usage tier）决定你的每分钟请求数和月度消费上限，等级靠累计充值往上走，急用高限额要找官方销售，而不是硬充钱。
- **有打折的口子。** Batch API 批量请求是五折价，Prompt Caching 的缓存读取部分能压到输入价的约十分之一。如果你跑的是批量数据处理，这两个加起来能省掉一大半成本。

问题在于，第 2 步对国内用户经常过不去。

## 三、国内卡为什么总被拒

三个独立的障碍叠在一起：

**支付。** 银联卡直接不行；国内银行发的 Visa/Mastercard 双币卡偶尔能过，但成功率不稳定，续费时被拒是常态。有人会想到 PayPal——Anthropic 确实收，但你的 PayPal 得绑一张外币卡才能付美元，国内 PayPal 默认绑的是银联，等于绕了一圈回到原点。

**验证。** 注册环节要海外手机号接短信，这一步就会筛掉不少人。

**环境。** 账号的使用地区、IP 类型和登录设备之间如果有明显矛盾，容易触发风控。这不是玄学，但也没有人能给你一份确定的规则清单——不同账号的实际结果差异很大。

这三件事性质完全不同。支付是商务问题，换一条付费路径就能解决；环境是工程问题，可以靠调整接入方式绕开。

> **订阅和 API 额度不通用。** 这句话值得再强调一遍，因为它是「Claude API 充值」相关问题里最常见的一次性错误。
